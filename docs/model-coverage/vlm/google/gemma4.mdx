[Gemma 4](https://ai.google.dev/gemma) is Google's next-generation multimodal Gemma family, supporting image-text inputs with a Mixture-of-Experts (MoE) language backbone at larger scales. NeMo AutoModel replaces the HF-native dense matmul over experts with the NeMo `GroupedExperts` backend, enabling Expert Parallelism (EP) through the standard MoE parallelizer.

## Available Models

- **Gemma 4 12B** (unified multimodal)
- **Gemma 4 E2B IT** (VL, dense, kv-shared layers)
- **Gemma 4 E4B IT** (VL, dense, kv-shared layers), **Gemma 4 E4B IT Assistant** (Assistant/drafter model for MTP)
- **Gemma 4 31B IT** (VL, dense)
- **Gemma 4 26B-A4B IT** (VL, MoE)

## Architecture

- `Gemma4UnifiedForConditionalGeneration` — unified 12B model
- `Gemma4ForConditionalGeneration`
- `Gemma4AssistantForCausalLM` (MTP drafter / assistant head for speculative decoding; co-trainable with the target Gemma 4 base using `Gemma4WithDrafter`)

## N-gram Embedding (experimental)

Dense Gemma 4 checkpoints (E2B, E4B, 31B) can be extended with an Engram-style
N-gram Embedding table, the mechanism Qwen3.8-Flash-Next ships pretrained. The
current token and its preceding tokens are hashed into a packed multi-head
table; the looked-up values are gated against the residual stream and, together
with a causal short convolution, added in front of one decoder layer
(`ngram_config.layer_index`). Hashed context never crosses the ids listed in
`eos_token_ids`, so packed documents stay separate.

The table is *added on top of the released checkpoint*: its value projection and
convolution start at zero, so the model is bit-identical to the base checkpoint
until the table is trained, and the base checkpoint loads without the new keys.
Training checkpoints of the augmented model contain the table under
`model.language_model.ngram.*` and load strictly. The table only becomes useful
after continued pretraining on a large token budget; fine-tuning data alone does
not populate it. Context and tensor parallelism, and the 26B-A4B MoE variant, are
not supported with the table.

```yaml
model:
  _target_: nemo_automodel.NeMoAutoModelForCausalLM.from_pretrained
  pretrained_model_name_or_path: google/gemma-4-E2B-it
  ngram_config:
    ngram_size: 3          # bigram + trigram heads, as in Qwen3.8-Flash-Next
    heads_per_ngram: 8     # 16 heads x 96 = the 1536 hidden width
    head_dim: 96
    rows_per_head: 666000  # 16 heads x ~666k rows x 96 = ~1B parameters
    layer_index: 1
    eos_token_ids: [1, 2]  # EOS and BOS: nanogpt shards delimit documents with BOS
```

Give the fresh table its own learning rate with `optimizer.param_group_overrides`
(see the example recipe); the pretrained backbone keeps the base rate.

## Try with NeMo AutoModel

**1. Clone and install from source** ([full instructions](/get-started/installation)):

```bash
git clone https://github.com/NVIDIA-NeMo/Automodel.git
cd Automodel
uv sync --locked --all-groups --all-extras
```

**2. Run the recipe** from inside the repo:

```bash
uv run automodel --nproc-per-node=8 examples/vlm_finetune/gemma4/gemma4_4b.yaml
```

<Accordion title="Run with Docker">
**1. Pull the container** and mount a checkpoint directory:

```bash
docker run --gpus all -it --rm \
  --shm-size=8g \
  -v $(pwd)/checkpoints:/opt/Automodel/checkpoints \
  nvcr.io/nvidia/nemo-automodel:26.06.00
```

**2. Navigate to the AutoModel directory** (where the recipes are):

```bash
cd /opt/Automodel
```

**3. Run the recipe**:

```bash
automodel --nproc-per-node=8 examples/vlm_finetune/gemma4/gemma4_4b.yaml
```
</Accordion>

See the [Installation Guide](/get-started/installation) and [VLM Fine-Tuning Guide](/recipes-e2e-examples/gemma-3-3n).
